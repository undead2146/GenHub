# Download acquisition acceptance criteria

Every supported publisher follows the same acquisition contract: resolve, deliver, process, validate, store. A download is successful only when the final manifest has been stored in CAS and contains the extracted payload files rather than its transport archive.

| Scenario | Acceptance criterion | Automated verification |
| --- | --- | --- |
| Generals Online card | The status line wraps rather than clipping the transfer rate, the stages never decrease, and the inactive card has no stale `5/5 Complete` message. | `ContentOrchestratorTests.AcquireContentAsync_ProviderReportsOutOfOrderPhases_ReportsMonotonicStages`; UI binding review in `ContentCardView.axaml`. |
| SuperHackers | Archive delivery may report internal extraction, but the displayed pipeline remains nondecreasing and reaches storage after validation. | `ContentOrchestratorTests.AcquireContentAsync_ProviderReportsOutOfOrderPhases_ReportsMonotonicStages`. |
| CNC Labs and AODMaps | A downloaded archive is extracted, the generated hashed staging manifest validates before CAS storage, then the stored manifest becomes CAS-backed. | `ContentValidatorTests.ValidateContentIntegrityAsync_StagedContentAddressableFile_ValidatesBeforeCasStorage`. |
| ModDB archive downloads | A ZIP or other supported archive is identified from the parsed filename, response headers, or file signature even when the redirect/Playwright destination has no extension. The transport archive is removed and the manifest lists payload files only. Unsupported archive formats fail before CAS storage with an actionable error; they are never stored as content files. | `ModDBManifestFactoryTests.CreateManifestsFromExtractedContentAsync_ExtensionlessZip_ExtractsPayloadInsteadOfManifestingArchive` plus a focused archive-format test. |
| ModDB map routing | A ModDB release categorised as a map (including `Singleplayer Map`) creates a `Map` manifest whose extracted payload targets `UserMapsDirectory`, so adding it to a profile makes it visible to the game. | `ModDBManifestFactoryTests` category-routing cases plus an in-game map-list smoke check. |
| ModDB release actions | Each release/addon row has a stable file identity and its own acquisition/profile state. Downloading or adding one row never marks the parent card or a different row as acquired, and Add to Profile uses that row's extracted manifest. | `ContentDetailViewModelTests` child-release acquisition and profile-action cases. |
| ModDB Cloudflare handoff | A detected challenge leaves the single persistent page open, displays the verification notice immediately (without a selector timeout), does not substitute the ten-item RSS feed, and pressing Search after verification loads page 1 of the real paginated catalogue. | Manual smoke check with a cleared `moddb` browser profile. Confirm no RSS request is logged while the challenge is visible, then solve it and Search. |
| ModDB managed Chromium | On a machine without Chrome, Edge, or a preinstalled Playwright browser, the first ModDB action provisions the app-owned Playwright Chromium runtime, then opens only the persistent ModDB page. Subsequent actions reuse that profile/cookies; no `about:blank` orphan or `--no-sandbox` warning remains. | `ManagedChromiumRuntimeTests` plus a clean-app-data first-run smoke check. |
| ModDB persistent browser and detail page | Selecting a ModDB card reuses or recovers the persistent context, parses its source URL, and populates Summary and available sections without `TargetClosedException`. The selected tab retains its purple selection affordance and the gallery does not occupy a fixed 400px blank rectangle. | Manual smoke check against a protected ModDB item; inspect logs for the absence of `TargetClosedException`. |
| ModDB current page contracts | The parser accepts the live `/addons/start/{id}` and `/downloads/start/{id}` routes, preserves the displayed archive filename, waits for the Playwright-backed page result before completing details, and maps addons/files/articles/media to populated tabs. | Focused ModDB discoverer/resolver/detail-view-model tests using representative current DOM markup. |
| Community Outpost hotkeys | Legionnaire's Hotkeys shows GenTool as a required dependency; profile activation auto-acquires/reconciles it. Cancelling the profile picker leaves the downloaded card actionable without a `Cancelled` status. | `GenPatcherDependencyBuilderTests.GetDependencies_LegionnairesHotkeys_AutoInstallsGenTool`; `CommunityOutpostManifestFactoryTests.CreateManifestsFromExtractedContentAsync_LegionnairesHotkeys_PreservesGenToolDependency`. |
| Publisher profile foundation | Adding an add-on that only requires a matching installation preserves an existing compatible publisher game client and its executable configuration. | `ProfileContentServiceTests.SelectReconciledGameClient_AddonOnlyRequirement_PreservesCompatiblePublisherClient` plus manual launch of an existing SuperHackers profile after adding Community Outpost content. |
| Required transitive dependencies | Adding or creating a profile with a manifest whose required dependency is `AutoInstall` acquires that dependency recursively before dependency resolution. A dependency marked `RequireExisting` blocks the operation with its name instead of producing an unlaunchable profile. | Focused `ProfileContentService` tests and a manual Control Bar Pro profile: `cbpc` is present in the final enabled content list before launch. |
| Control Bar variants | All downloaded resolution manifests are presented as a variant family when adding to an existing profile or creating a new one; no resolution is silently selected solely because it was extracted first. | Manual smoke check with Control Bar Pro: choose two different resolutions in separate profile operations and verify the selected manifest ID/name. |
| AODMaps map installation | Every discovered and extracted AODMaps item is a `Map` with `UserMapsDirectory` payload targets, so Add to Profile succeeds and the map appears in-game. | Inspect an AODMaps manifest after download and run an in-game map-list smoke check. |
| Subscribed catalogs and publisher tabs | A local catalog file or HTTP(S) catalog can be subscribed without an unsupported-scheme error; its sidebar entry, details tabs, and supplied card metadata are visible after confirmation. Both catalog and ModDB tab providers are registered at startup. | `CatalogTabProviderTests` and a focused subscription-store/URI parsing test, followed by the sample-catalog smoke check. |
| Curated publisher chrome | Generals Online, Community Outpost, and TheSuperHackers expose neither a search box nor filters, because their curated content does not support meaningful queries. | `DownloadsBrowserViewModelTests.SelectPublisher_CuratedPublisher_HidesSearchAndFilters`. |
| AOD Maps browse UI | AOD Maps opens its player-count filters by default. Cards have a real map title, player-count badge, and meaningful type/version metadata; no placeholder `0` badge is shown. | `DownloadsBrowserViewModelTests.SelectPublisher_AodMaps_ExposesAndOpensFiltersByDefault` plus focused AOD discoverer/card metadata tests. |
| CNC Labs maps | New map manifests route every extracted map payload to the game user Maps directory. Previously-downloaded map manifests incorrectly marked Workspace are normalized during profile preparation. | `CNCLabsManifestFactoryTests.CreateManifestsFromExtractedContentAsync_MapArchive_RoutesPayloadToUserMapsDirectory`; manual launch and in-game map-list smoke check. |

Release gate:

1. Run the focused tests in the table, then the full Core test project.
2. Run `dotnet build GenHub/GenHub/GenHub.csproj --no-restore -nologo` with zero warnings and errors.
3. For each live publisher (Generals Online, SuperHackers, CNC Labs, AODMaps, ModDB), download one archive and inspect the resulting manifest: no `.zip` transport file, at least one extracted payload file with a CAS hash, and the card transitions to Add to Profile only after acquisition succeeds.
